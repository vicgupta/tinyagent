# Built-in tool notes

## Notes

- `read_file` takes optional `offset` (1-based start line) and `limit` (max lines) to read part of a large file. A partial read ends with `[lines A-B of N]`; with neither set, it returns the whole file as before. With `--tool-output-files`, over-limit tool results are saved to files the model reads this way; see [Tool output files](long-runs.md#tool-output-files). Binary files are rejected; use `bash` (for example, `file` or `xxd | head`) to inspect them.
- `edit_file` replaces exactly one occurrence of `old_str` and fails if it occurs zero or several times. Pass `replace_all: true` to replace every occurrence (for a rename); it still fails if there are none, and returns `ok (N replacements)`.
- `grep` uses Go regular expressions by default. Set `fixed_strings: true` for literal text, e.g. `{"pattern":"func(","path":".","include":"*.go","fixed_strings":true}` finds literal `func(` in Go files without regex escaping.
- `grep` accepts `ignore_case: true` for case-insensitive content searches, e.g. `{"pattern":"error","path":".","include":"*.log","ignore_case":true}` matches `error`, `Error`, and `ERROR` in `.log` files. The default is case-sensitive; inline regex flags such as `(?i)` still work. The `include` glob stays case-sensitive.
- `grep` accepts `context_lines` from 0 to 20 to include that many surrounding lines on each side, e.g. `{"pattern":"connection failed","path":"internal","include":"*.go","fixed_strings":true,"context_lines":1}`. Matches use `file:line: content`; context uses `file-line- content`, and `--` separates excerpts. The default is 0 and preserves match-only output. Context excerpts merge when they overlap or touch; positive-context results stop at 500 matches or 500 source lines and say when output may be incomplete. Use `read_file` with `offset` and `limit` for a larger or targeted excerpt.
- Each `bash` call runs in a new process; `cd` and exported variables don't carry over. On timeout the whole process group is killed (Unix). The model can pass an optional `timeout` (1 to 600 seconds) on a `bash` call to override `bash_timeout_seconds` for that command.
- With run streaming enabled (the default), `bash` and configured `command_tools` produce live previews in `--json`, chat and web without requiring `stream: true`. Explicit bash `stream: false` silences that call; `--no-stream` disables all previews, even with `stream: true`. In one-shot human mode, implicit previews appear on stderr after one second (`-v` shows them immediately); explicit `stream: true` shows output immediately on the normal progress writer (stderr with `--output-schema`, otherwise stdout). The result returned to the model is unchanged.
- Live previews are capped at 256 KiB per call (including a `[live output truncated]` marker, live stream only). With secret redaction configured, complete lines are buffered and redacted together so secrets split across writes are masked; an oversized unterminated line is discarded, and a final partial line flushes when the tool returns. Previews are ephemeral: only the final `tool.result` enters the log, trace or trajectory. Direct Go callers may use `tools.WithOutput(ctx, callback)`; `Executor.Stream` remains supported for explicit bash `stream: true`.
- For servers, watch modes, and other long-running commands, `start_process` runs `bash -c <command>` in the background and returns a process id (`p1`, `p2`, ...) with its first output. `read_process` previews the output of its wait when streaming is enabled and returns only output produced since the last read, optionally waiting up to `timeout` milliseconds (max 60000) for some, or just the last `tail` lines. `stop_process` kills the process and its children (the whole process group on Unix) and reports the exit status and unread output. For example: start a server, `read_process` until it logs "listening", run tests against it, then stop it.
- At most `max_background_processes` (default 4) run at once, and each keeps only its last 1 MiB of output; a read notes how many bytes were dropped. When the run ends for any reason (submission, a limit, Ctrl-C, or an error), every background process still registered is killed and its status and output tail are saved as `background_processes` in the trajectory, so nothing is left running. On Windows only the `bash` process itself is killed.
- Path sandboxing is lexical: `..` and absolute paths outside `--cwd` are rejected, but a symlink inside the root that points outside it is followed. `bash` isn't sandboxed unless you pass `--sandbox` or `--env container` (see Sandboxing commands and Execution environments); without them, only run it on code you trust.
- Cost uses a small built-in price table (`internal/model/runtime.go`). Unknown models cost $0 unless you set the price in the config (top level, or per model under a [named provider](providers.md#named-providers)), so `--cost-limit` does nothing for them. With a positive cost limit, tinyagent prints a warning on stderr before the first request when the `openai`, `openrouter`, `anthropic` or named-provider model has no price, naming `input_price_per_mtok` and `output_price_per_mtok`. The run continues as normal.
- The `anthropic` provider turns on [prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching) for every request, so each step reads the history the previous step already sent from the cache instead of paying full price for it again. Input tokens in the summary and trajectory include cached tokens. Cost prices cache writes at 1.25× the input price and cache reads at 0.1× (less on models where Anthropic charges less, such as 0.05× for Claude Opus 5.5 and Sonnet 5.5). `input_price_per_mtok` overrides the base price and the multipliers apply on top.

## Tool error messages

Every tool error the model sees states **what went wrong** and **what to try next**, joined by a semicolon — the same shape as `edit_file`'s unique-match error (`old_str occurs 3 times in x.go; add surrounding context to make it unique`). A bare `failed` is avoided so the model can fix the call instead of retrying blindly.

Examples:

| Tool | Cause (excerpt) | Next step (excerpt) |
|------|-----------------|---------------------|
| `edit_file` | `old_str not found in x.go` | `read the file and copy the exact text to replace` |
| `bash` | `command timed out after 30s and was killed` | `retry with a higher timeout … or split the work` |
| `web_fetch` | `host … is not in web_fetch.allowed_domains` | `pick an allowed host or ask to update …` |
| `web_search` | `all providers failed: …` | `Try again in a minute or rephrase …; … web_fetch` |
| `lsp` | `no lsp server configured for .rs files` | `configure an lsp.servers entry …` |
| MCP tools | `MCP server docs call failed: …` | `fix the server or its config, then start a new run` |

Permission and `file_access` denials follow the same pattern. New tool error paths should use `tools.Actionable` / `tools.Actionablef` (or the MCP helpers) so tests can assert the wording.
